# Save scum - dark arts, for learning only

The user (2026-11-02): "you can save the game before you do tests and reload the game after if you don't
like the results. This is called save scumming, and is only good for learning. In real games you don't
save scum." And: "Save scumming is dubiously a form of cheating."

## The line
- **Allowed:** learning sessions, meaning learn-to-play tests, manual-first checks, hypotheses from a
  game's guide, an unknown button or order, and how often a dice roll goes each way.
- **Never:** in a real game (a battle or campaign played to win, or one the user is watching as a real
  game). There every result stands, good or bad, and losses are part of the game.
- **Not sure?** Treat the game as real and ask the user. The FoG II battle 2 is real play unless he says
  otherwise.
- Say so when I use it, e.g. "saved before the test, reloading". Never hide a reload.
- It doesn't loosen the other fair-play rules: no game modification, no data hooks, read the screen.

## How
1. Save under a name that says what it is: `LEARN-<test>-before`. Never overwrite one of the user's saves.
2. Do the test. Write down what happened, with the turn and what was on screen, before reloading. The
   lesson is the point.
3. Reload. Photograph the screen to check that the state really went back.
4. Repeat if the test is about chance: several trials give the spread, which one result doesn't.
   Check whether reloading re-rolls the dice or the game fixes a seed (some games do). That is itself
   a lesson for the game's guide.
5. Delete my LEARN- saves when the session ends, or tell the user they're there.

## Per game
- **FoG II Medieval:** Load/Save is in the Esc menu or the Briefing panel (the triangle under the
  score). You can save at any time except during the enemy turn (manual 20, p.162). Saves go in
  Documents/My Games/FieldOfGloryMedieval/SAVES (Proton prefix). From the main menu, L loads the last
  save (manual 28). Whether a reload re-rolls combat is not yet tested.
